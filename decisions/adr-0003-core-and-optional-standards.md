# ADR-0003: Core / Optional Standard と Recommendation の区分の基準

**状態**：採用
**日付**：2026-10-11

## 状況

stockroom には `docs/ARCHITECTURE.md` などに多くの判断がある。すべてを Standard にすると読む量が増えて守られなくなり、何も Standard にしないと配布や更新で実害が出る。どれをどの層に置くかの基準が要る。

## 決定

| 層 | 基準 | 例 |
|---|---|---|
| **Core Standard** | すべてのツールに当てはまり、**不一致そのものが実害** になる（更新が届かない、データが壊れる、鍵を失う、Web ビューが無防備、ログが無くて調べられない） | CSP、updater、識別子を変えない、ログ、3 か所のバージョン、必須 gate |
| **Optional Standard** | その機能を持つツールにだけ当てはまり、持つなら不一致が実害になる | 127.0.0.1 の受付、複数ツール同居の tag と feed、トレイ常駐 |
| **Recommendation** | 選択であり、別の選択をしても他のツールやユーザーに害が無い | zustand、rusqlite、tiny_http、Bun |
| **Playbook** | 判断ではなく手順。間違えても手戻りで済む | リリース、鍵の生成、モック |
| **ツール固有** | 1 つのツールでしか使われていない | モード（画像 / フォント）、ライブラリの構造、作業台 |

昇格は README「知識・資産の成熟」の段階に従う。**2 つ目のツールで同じ形が有効だった** ものだけ Recommendation / Playbook に上げ、**不一致が実害になる** ものだけ Standard に上げる。

## 理由

- stockroom と Shelf の 2 つで有効だったものに限ることで、今の Core は実例のあるルールだけになる。
- 「実害」を基準にすると、好みの話（インデント、命名）を Standard に入れずに済む。それらは Linter と fmt に任せる。

## 影響

- Standard の各節は「出どころ」として stockroom / Shelf のファイルを指す。指せないルールは Standard に書かない。
- ツール固有の判断は各ツールの `docs/` と `decisions/` に置き、Platform に写さない。

## 見直す条件

- 3 つ目のツールが Core Standard の半分以上に ADR で逸脱した場合（Core が広すぎる）。
- 同じ事故（更新が届かない等）が 2 回起きた場合（Core が狭すぎる）。

# ファイル管理のアプリ（検討）

**状態**：何を作るかを決めている段階（2026-11-22 〜）。コードはまだ無い。名前・リポジトリも未定。
作ると決まったら、この文書はそのアプリのリポジトリ（`decisions/project-context.md` ほか）へ移す。

**結論（今の案）**：PDF・オフィス文書・テキストを、**元の場所に置いたまま** タグ・仮想フォルダ・メモで横断的に整理するアプリ。
ファイルを取り込まず、書き換えず、動かさない。強みは「散らばったファイルを、置き場所を変えずにまとめて見つけられる」こと。

## 経緯

- Stockroom（hamirilo/stockroom）は v0.46.0 で扱う種類を画像と動画だけに絞った。強みの「見た目で探して選ぶ」が活きない種類を外した（stockroom の `docs/FILE_APP.md`）
- 外したのは、ファイル（PDF・オフィス文書）、テキスト（Markdown・テキスト・CSV）、ブックマーク（URL）。その受け皿として検討する
- フォントを別アプリ（Typecase）に分けた前例がある（stockroom の `docs/FONT_APP.md`）

## 決めたこと

| 論点 | 決定 | 理由 |
|---|---|---|
| 強みの軸 | **置き場所の整理**。中身での検索やプレビューは補助 | 「見て選ぶ」が活きない種類では、見つける手がかりは名前・場所・付けた情報になる |
| 扱う種類 | PDF・オフィス文書・テキスト（Markdown・テキスト・CSV） | |
| ブックマーク | **扱わない** | ブラウザとの連携と通信が要る（リンク切れの確認・更新・中身の保存）。デスクトップアプリの「URL を取りに行かない」原則とぶつかる。要るなら Web アプリとして別に検討する |
| ファイルの持ち方 | **元の場所のまま参照する**。ライブラリへの取り込み（複製）はしない | 置き場所（共有ドライブ・OneDrive など）は業務の都合で決まっていて、アプリ側に移せない。複製すると元と食い違う |
| 対象の範囲 | **登録したフォルダの配下** を基本にし、**外のファイルも個別に足せる** | 登録フォルダは全体を把握しやすく、移動も追いやすい。個別の追加は「この 1 つだけ」に対応する |
| 移動・改名の追跡 | **開いたとき（起動・再読み込み）に照合する**。常時の監視はしない | 共有ドライブでは監視の通知が届かないことがある。照合の順は下の「照合」 |
| 実ファイルの操作 | **しない**。アプリが書くのは自分のデータ（タグ・仮想フォルダ・メモ）だけ | 元のファイルを壊さない・動かさないことを保証できる。移動・改名は Finder / エクスプローラーで |
| 全文検索 | **後回し**。最初は名前・場所・タグ・メモで探す | 整理の仕組みを先に固める。入れるときは Stockroom の文字コード判定（Shift_JIS）を使う |
| Feedability の記事とリンク | **受けない** | ブックマークを扱わないのと合わせる。記事は Feedability 側で `.md` に書き出せば、普通のテキストとして扱える。待ち受けポートも増やさない |
| Stockroom から外したコード | **部品だけ持ってくる**。プレビュー（Quick Look・Windows.Data.Pdf・Office の PDF 変換）と、テキストの文字コード判定・読み書き | ライブラリ・取り込みの作り（複製が前提）は合わないので、新しく考える |
| 土台 | desktop-platform の Standard に従い、共通の部品（desktop-base）を使う。無ければ `playbook/new-tool.md` の「desktop-base がまだ無いとき」 | stockroom の `docs/FONT_APP.md` の「方針」4 |
| この文書の置き場 | desktop-platform の `docs/`（作ると決まったらアプリのリポジトリへ移す） | |

## Finder やエディタで足りないか

作らない結論もありうるので、足りない点を挙げておく。下のどれも要らないなら作らない。

| 欲しいこと | Finder / エクスプローラーでは |
|---|---|
| フォルダをまたいでまとめる（「案件 A」の資料が共有ドライブと手元に散らばっている） | ショートカット・エイリアスを手で作るしかない。元が動くと切れる |
| タグ | macOS の Finder タグはあるが、Windows には無い。共有ドライブ上ではほかの人と混ざる・消えることがある |
| メモ（このファイルは何か、どの版が最新か） | 付けられない（ファイル名に書き込むしかない） |
| 種類をまたいだ一覧（PDF・Excel・CSV を一緒に、タグで絞る） | 検索条件の保存はあるが、OS ごとに違い、タグとは組み合わせにくい |
| 中身の確認 | Quick Look（macOS）はある。Windows のプレビューウィンドウは種類によって出ない |

アプリの情報（タグ・メモ）は自分の端末のアプリのデータに持ち、元のファイルにも共有ドライブにも書かない。

## 照合

起動時と再読み込みのとき、覚えているファイルを次の順で探す。

1. 覚えているパスにある → そのまま
2. 無い → 登録フォルダの中から、ファイル ID（macOS の inode・Windows の File ID）が同じものを探す
3. それも無い → 大きさとハッシュが同じものを探す
4. 見つからない → **行方不明** として残す（タグ・メモは消さない）。手でつなぎ直すか、外せる

登録フォルダに新しく増えたファイルは、タグ無しの項目として一覧に出る。

## 詰めること

- 名前・`identifier`・リポジトリ（人が決める）
- 画面：一覧（リスト中心か）、仮想フォルダとタグの見せ方、行方不明の見せ方。UI Standard の「レイアウトの安定」に沿う
- データの置き場：`app_data_dir()` の SQLite か、ユーザーが選ぶ場所か（複数台で同じ整理を使いたいか）
- 照合の重さ：登録フォルダが大きい・共有ドライブが遅いときの読み方（差分だけ・後ろで読む）
- 開く操作：既定のアプリで開く、Finder / エクスプローラーで表示、パスをコピー。テキストの編集は外のエディタに任せる（アプリ内で編集しない。「エディタになる」懸念への答え）
- プレビュー：Stockroom の部品をどこまで持ってくるか（Office の PDF 変換は Office が要る）
- 全文検索を入れる時期と範囲
- 社内版（jazmf-dx）で使うか
